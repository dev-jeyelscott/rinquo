Usage Guidelines

When to Register New UI

  • Register new reusable UI when you create or materially change it
  • Ensure the component solves a repeated problem (appears in 2+ places or 2+ reference designs)
  • Build using primitives from the UI library
  • Include TypeScript types and at least one test case
  • Do not register arbitrary page-local fragments or one-off utility classes

Accessibility Requirements

  • All components use native HTML semantics where possible
  • Keyboard navigation support (Tab, Arrow keys, Escape)
  • Visible focus states (blue outline ring)
  • Color never used alone; always paired with text or icon
  • Minimum WCAG AA contrast (4.5:1 for text)
  • Touch targets minimum 44px x 44px on mobile
  • Respects prefers-reduced-motion for animations

Responsive Design

  • Mobile-first: design for small screens, then enhance with breakpoints
  • Use Tailwind's md: (768px) and lg: (1024px) prefixes
  • Touch-friendly targets on mobile (44px minimum)
  • Simplified forms and single-column layouts on mobile
  • Test at: mobile (375px), tablet (768px), desktop (1024px+)

Deprecation Rules

  • Mark components as deprecated in the registry with a successor field
  • Update existing consumers within one sprint
  • Keep the registry entry for historical reference
  • Never delete deprecated entries without approval
